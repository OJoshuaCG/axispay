# Internationalization (English + Spanish)

Every user-facing string goes through `__()`, stored in PHP array files under `lang/en/` and `lang/es/`. The request locale is picked by `App\Http\Middleware\SetLocale` and drives text, `<html lang>`, money and dates. This page is for anyone adding copy, a screen or a language.

## Quick path: add a string

1. Pick the file by domain (table below) and add the key to **both** `lang/en/<file>.php` and `lang/es/<file>.php`.
2. Use it: `{{ __('checkout.pay_now') }}`, or `:label="__('checkout.pay_now')"` for a component prop.
3. Check `/?lang=es` at 320px: Spanish is 20–30% longer and must still fit ([responsive.md](responsive.md)).

## Conventions

| Topic | Rule |
|---|---|
| Format | PHP array files (`lang/<locale>/<domain>.php`), nested keys, read as `domain.group.key` |
| Why not JSON | Framework files (`validation.php`...) are already PHP; arrays group keys by domain, allow translator comments, and stable keys survive copy edits (JSON keys *are* the English text, so fixing a typo breaks every translation) |
| Key names | `snake_case`, describe meaning not wording: `checkout.pay_now`, not `checkout.pay_now_button_blue` |
| Placeholders | `:name` style: `__('welcome.copyright', ['year' => $y, 'app' => $name])` |
| Register (es) | Neutral professional Spanish, formal *usted* ("Vuelva a visitarnos", "Inténtelo de nuevo"); no regional forms (*vos* and voseo verb forms) or local slang |
| Code | Keys, comments and identifiers in English |

### Which file?

| File | Holds |
|---|---|
| `ui.php` | Shared chrome and component defaults: skip link, theme toggle, language switcher, button loading text, alert prefixes, amount fallback |
| `payments.php` | Payment vocabulary; `payments.status.<enum value>` feeds `PaymentStatus::label()` |
| `welcome.php`, `design-system.php` | Copy of the page with the same name (one file per page view) |
| `validation.php`, `auth.php`, `passwords.php`, `pagination.php` | Framework messages, published with `php artisan lang:publish` and translated in `lang/es/` |

New feature area (checkout, dashboard): create `lang/{en,es}/<area>.php`. Add readable field names for validation messages in `validation.php` → `attributes` (`'card_number' => 'número de tarjeta'`).

## Rules that prevent broken translations

| Do | Don't |
|---|---|
| One key per full sentence, with placeholders | Concatenate fragments: `__('a').' '.$name.' '.__('b')` (word order differs between languages) |
| `trans_choice('payments.items', $n, ['count' => $n])` with `{0} No items\|{1} :count item\|[2,*] :count items` | `$n === 1 ? 'item' : 'items'` |
| Inject HTML (links) as escaped placeholder values: see the typography example in `design-system.blade.php` | Put markup in translation values, or split a sentence around a link |
| Pass translated strings to JS through `data-*` attributes (`data-loading-label`) | Hardcode user-facing text in `resources/js/*.js` |
| Translate sr-only text, `aria-label`, `title`, placeholders | Assume invisible text does not need translation |
| Keep `lang/en` and `lang/es` key sets identical | Rely on the `en` fallback to hide a missing Spanish key |

Missing keys fall back to `fallback_locale` (`en`); if English is missing too, the raw key is shown. Check parity with a quick script before merging (compare flattened key sets of both folders).

## How the locale is chosen

`SetLocale` runs on every `web` request (appended in `bootstrap/app.php`, after cookie decryption). First valid value wins; unsupported values are ignored at every step.

| Priority | Source | Persisted? |
|---|---|---|
| 1 | `?lang=es` query parameter | Yes: sets the `locale` cookie |
| 2 | `locale` cookie (a previous explicit choice) | Already stored |
| 3 | `Accept-Language` header, best match by primary subtag (`es-CL` → `es`) | No |
| 4 | `config('app.locale')` (`APP_LOCALE`, default `en`) | No |

Then it calls `Locales::apply()`: `App::setLocale()` (Carbon follows through its `LocaleUpdated` listener) and `Number::useLocale()`. Responses carry `Vary: Accept-Language, Cookie` so shared caches never mix languages.

Cookie: `locale`, 1 year, `SameSite=Lax`, `HttpOnly`, encrypted like every Laravel cookie, `secure` per `config/session.php`. There are no locale URL prefixes, so no `hreflang` tags.

### The switcher

`<x-language-switcher>` (inside `<x-site-controls>`) posts `locale` and the current URL to `POST /locale` (`locale.update`, CSRF-protected). `LocaleController` validates the code, sets the cookie and redirects back. The redirect only accepts same-origin relative paths (`//host` is rejected) and drops `?lang=` so an old query parameter cannot override the new choice. It works without JavaScript. Props and ARIA: [components.md](components.md#language-switcher-x-language-switcher).

## Add a locale

1. Add it to `config/app.php` → `supported_locales` (`'pt' => 'Português'`, native name).
2. Copy `lang/en/` to `lang/pt/` and translate every file (framework files included).
3. Check `/?lang=pt` at 320px, both themes, with the viewport check ([responsive.md](responsive.md#viewport-check)).

Nothing else changes: the middleware, switcher and formatters read the config.

## Money and dates

| What | Rule |
|---|---|
| Currency | Per **transaction**: always pass `currency` from the payment |
| Locale | Per **viewer**: leave `<x-amount locale>` unset; it follows the request locale |
| Amount format | ICU decides: `en` `$1,234.56`, `es` `1.234,56 US$` (ICU 77). Never hand-build separators |
| Dates | Carbon, locale-aware: `$date->isoFormat('LL')`, `$date->translatedFormat('j F Y')`. Wrap in `<time datetime="{{ $date->toIso8601String() }}">` |
| Numbers | `Number::format()`, `Number::percentage()` use the request locale via `Number::useLocale()` |

Details: [payments-ui.md](payments-ui.md#amounts).
